# GitHub에서 이곳 APK 업데이트 정보를 자동 갱신

사용자가 승인한 범위는 현재 `selfness-byte/mapswork` 원격 저장소의
`codex/nearby-shop-alert`에 APK가 게시되면 GitHub Actions에서 실제 APK를
검증하고 두 브랜치의 업데이트 정보와 설치 안내를 함께 게시하는 것이다.
원본을 확보하지 못한 `245690b` 복구는 별도로 보류한다.

- APK의 패키지명은 `com.selfness.mapswork`, 최소 Android 버전은 26 이상이다.
- 기존 시험판 인증서 SHA-256은
  `80dfd84789e5c205b319562bf99bd33500b64000695594f1b8dbf2b58638cf40`이다.
- 파일명, 실제 버전 코드·이름, 크기(최대 80MiB), SHA-256과 APK 서명을 확인한다.
- `downloads/update.json`과 `main`의 `이곳/update.json`은 같은 결과로 만든다.
- 양쪽 README의 버전과 다운로드 주소도 갱신한다. APK 주소는 파일을 게시한
  40자리 Git 커밋에 고정한다. APK와 체크섬이 같은 커밋에 있어야 한다.
- 기존 정보보다 버전 코드 또는 버전 이름이 내려가면 실패한다. 같은 버전을
  다른 바이너리로 교체하지 않는다. 검증이 끝나기 전 메타데이터를 게시하지 않는다.
- 두 브랜치 변경은 일반적인 atomic push로 함께 게시한다. 원격이 동시에 바뀌면
  실패하고 다시 실행해 최신 상태에서 검증한다. 변경이 없으면 커밋하지 않는다.
- APK 게시가 Actions에서 이루어질 때는 재사용 가능한 게시 워크플로의 후속
  작업이 갱신 워크플로를 직접 호출한다. GITHUB_TOKEN의 push 이벤트에 의존하지 않는다.
- 기존 APK·검증 기록·미게시 앱 소스 변경을 보존한다. 앱 소스를 main에 병합하거나
  강제 푸시하거나 브랜치 보호·계정 권한을 바꾸지 않는다. Firebase 배포는 하지 않는다.
- 구현·푸시와 GitHub 서버에서 실행한 결과를 각각 보고한다.
